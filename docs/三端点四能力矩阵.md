## 0. 三个端点的界定

| 简称 | 域名 | 来源项目 | 说明 |
|------|------|----------|------|
| **QoderCN** | `openapi.qoder.com.cn` + `gateway.qoder.com.cn` | qoder2api（`RegionCN`）、qoderwork2api、本项目 | 国内站 |
| **QoderCOM** | `openapi.qoder.sh` + `api1/api2/center.qoder.sh` | qoder2api（`RegionGlobal`）、Orchids-2api | 国际站（`.sh`，`qoder.com` 授权页） |

## 3. 关键结论

1. **本项目当前只接入了 QoderCN**，且能力 2/3/4 已达可用水平。
2. **唯一缺口是能力 1（签到）**，且 **只有 `qoder2api-CN` 和 `qoderwork2api` 实现了该域的签到**；
   `qoder2api-CN` 的签到是双路径最全版本，是**本项目补齐签到的唯一合适参考**。
3. **`Orchids-2api` 是 QoderCOM 专用**（`.sh`），且**完全没有签到实现**，接 QoderCOM 时它可作为能力 2/3/4 参考，但签到无参考。
4. **QoderWork 与 QoderCN 同域名**，代码上二者仅在 COSY 细节与模型表有差异；qoderwork2api 的签到是 `daily-check-in` 单路径，可作为交叉验证。
5. 若未来要接入 **QoderCOM**，需要新渠道（OAuth client_id 不同、凭据不通用已实测），且三个仓库都**没有 QoderCOM 签到**——需自行逆向。
